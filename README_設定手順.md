# MyLife Calendar v2 — 設定手順

この版はソース実装とローカル自動テストを終えた段階です。Google実アカウントでの認可・共有権限・GAS公開、GitHub Pages公開、iPhone実機検証は未完了です。実運用開始前に docs/検証状況.md の実機項目を完了してください。

## 構成

- index.html / styles.css / app.js：月間、週間、日別、入力、設定、画像OCR
- core.js：日本時間の日付、OCR候補抽出、起床時刻計算
- backend/Code.gs：2人の本人認証、権限検査、保存の直列化、Google同期、競合検出
- shift-sync/Code.gs：別のGASプロジェクト。元シフト表を読み取るだけで勤務カレンダーを更新
- service-worker.js / manifest.webmanifest：PWA。アプリ資材のみキャッシュ

勤務シフト管理アプリは変更しません。無料枠を前提とし、有料APIは使用しません。Googleの利用上限は適用されます。

## 1. GitHub Pages

独立した空の公開リポジトリ（例 mylife-calendar）にこのフォルダーの内容を配置します。既存のMyLifeリポジトリには入れません。

Settings → Pages → Deploy from a branch → main / (root)。公開URLはGitHubが表示したものを使用します。サブディレクトリにも対応する相対パスです。公開コードに予定データ、2人のメールアドレス、シフト元のID、設定済みサーバープロパティ、トークンを入れません。config.example.jsonは架空の例です。

## 2. Google CloudのOAuth設定

無料のGoogle Cloudプロジェクトを作成し、Google Sheets API、Google Calendar API、Google Drive APIを有効化します。請求先登録・有料APIは不要です。

Google Auth Platformでアプリを設定し、対象を外部・テスト用として2人のGoogleアカウントをテストユーザーに登録します。ウェブアプリケーションのOAuthクライアントを作成します。

承認済みJavaScript生成元は実際のPagesのオリジン（パスを除いた https://ユーザー名.github.io）。クライアントIDは公開識別子であり、秘密鍵ではありません。クライアントシークレットはPWAに入力しません。

使用スコープ：openid / email / spreadsheets / calendar / drive.metadata.readonly。Driveのメタデータ権限はシートの共有設定を確認するためです。Google同意画面で実際の権限を確認してください。権限変更・認可は本人が行います。

この版のGoogleトークンはメモリ内のみです。アプリの再起動や有効期限切れでは「Googleで接続」を再度押します。バックグラウンドでの永続ログイン・無期限の双方向同期は実装していません。

## 3. 初回のデータベース・カレンダー作成

公開ページの設定でクライアントIDを入力しGoogle接続します。まだ同期サーバーが未設定なので初回読み込みはエラーになりますが、認証済みの状態で作成ボタンを使用できます。

本人が作成するもの：

1. 共有シート1個（eventsタブ、v2の20列ヘッダーを作成ボタンが設定）。恵里子さんを編集者として追加し、一般公開・リンク共有はOFFにします。
2. 本人用の個人シート1個。誰にも共有しません。所有者本人のみです。
3. MyLife共有カレンダー1個。2人だけを所有者／予定の変更権限に設定します。一般公開・ドメイン共有はしません。
4. 本人専用のMyLife個人カレンダー1個。本人だけを所有者とします。既存の共有設定のあるメインカレンダーは個人用に指定しません。
5. MyLife勤務カレンダー1個。元シフトにアクセスできる本人が所有者、相手は「予定の表示」のみ。PWAでは所有者から見ても勤務イベントは読み取り専用です。Google上の所有者の編集権限をなくすことはできないため、所有者は手修正しない運用とします。

相手は自分のGoogleアカウントで個人シートと個人カレンダーだけを作成します。共有シートと共有カレンダーは同じものを使用します。

共有シートを2人だけの編集権限にしないとサーバーは保存を拒否します。個人シート・個人カレンダーに他人の権限や一般公開がある場合も拒否します。予定データはブラウザのローカル保存に複製しません（体験モードは別の端末内データ）。

## 4. 同期用GAS

新しい独立したApps Scriptプロジェクトに backend/Code.gs を配置します。プロジェクト設定でマニフェストを表示し backend/appsscript.json を使用します。

プロジェクト設定 → スクリプトプロパティに MYLIFE_CONFIG を追加し、backend/config.example.json のJSONを実値に置き換えて保存します。usersには2人のGoogleメールアドレスと各個人DB・カレンダーを登録します。共有先と個人先を同じIDにしないでください。これはサーバー内の設定でありGitHubに保存しません。

デプロイ → 新しいデプロイ → ウェブアプリ：実行するユーザーは自分、アクセスは全員。匿名アクセス可能でも、予定操作には許可したOAuthクライアントからの有効なGoogleアクセストークンと2人のメールアドレス照合が必須です。URLを知っているだけでは予定を操作できません。スクリプト所有者のGoogle権限でDBを操作することもありません。全API呼び出しはリクエスト本人のトークンを使用します。

デプロイ承認を行い /exec URLを取得します。両端末のPWA設定へ同じGAS URLとOAuthクライアントIDを入力します。「Googleで接続」でログイン後、サーバーからその本人の保存先だけを取得します。

※ブラウザからGASへの通信はtext/plainのPOSTとContentServiceのリダイレクトを利用します。この組み合わせのCORS・iPhone動作は実環境で必ず確認します。失敗時に安全でない直接保存方式へ切り替えません。

## 5. 勤務同期用GAS（別プロジェクト）

既存の勤務シフト用GASには追加しません。さらに別の独立したプロジェクトを作り、shift-syncのCode.gsとappsscript.jsonを配置します。

スクリプトプロパティ：

- SHIFT_SOURCE_ID：既存の「辻岡シフト」のスプレッドシートID
- SHIFT_WORK_CALENDAR_ID：MyLife勤務カレンダーID

タイムゾーンをAsia/Tokyoに設定します。元シートに対する権限は読み取りのみのOAuthスコープです。syncMyLifeShiftsを手動実行し、作成・更新数とカレンダーを確認後、installMyLifeTriggerを実行します。15分間隔のトリガーが作成されます。

読み取りは各週の日付・勤務先・開始・終了の4行だけです。備考行は取得しません。21日〜翌20日の月度を識別し、対象の勤務を日付の安定キーで更新します。H等の休日は該当する管理イベントのみ削除します。不明な勤務先・不正な勤務時刻ではGoogleの予定を書き換える前に停止します。

日付セルや月度タブそのものが消えて対象日を読めなくなった場合、その日の既存イベントを推測で削除しません。シート構造の大きな変更・タブ削除は手動確認が必要です。通常の変更は日付を残して勤務欄をHにする方法を使用します。

## 6. iPhone

Safariで公開ページを開く → 共有 → ホーム画面に追加。ホーム画面から起動し、設定・Google認可・共有・個人・画像取り込みを実機検証します。SafariとPWAの保存領域・認可状態は同じとは限らないため、ホーム画面側でも設定してください。

画像は写真／スクリーンショットを選択します。Tesseract.jsで日本語OCRを実行し、日付・開始・終了・タイトル候補をフォームへ入れます。保存は利用者が確認して押すまで実行しません。画像をOCRサーバーへアップロードしませんが、初回はCDNからライブラリと言語モデルを取得します。小さな文字や斜めの画像、HEICは実機依存です。読み込めない場合はスクリーンショットやJPEGを使用してください。
