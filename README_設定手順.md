# v2.3 Google実接続の手順（本人がPCで1回だけ行う）

通常の設定画面に出るのは接続状態・接続/解除・すべて同期・最終同期だけです。IDを2人の端末へ入力する必要はありません。既存の予定・設定・DBは削除や初期化をしません。

所要時間は30〜40分ほどです。Windows PCのChromeで、**本人のGoogleアカウントだけ**にログインした状態で行ってください。

## A. Google Cloud（OAuthクライアント）

1. https://console.cloud.google.com/ を開き、上部のプロジェクト選択から「新しいプロジェクト」を作ります。名前は「MyLife Calendar」にします。
2. 「APIとサービス」→「ライブラリ」で、次の3つを検索して「有効にする」を押します。
   - Google Sheets API
   - Google Calendar API
   - Google Drive API
3. 「Google Auth Platform」（または「OAuth同意画面」）を開きます。
   - アプリ名：MyLife Calendar。ユーザーサポートメールには本人のアドレスを指定します。
   - 対象：**外部**を選びます。
   - 「対象」→「テストユーザー」に、**本人と恵里子さんのGoogleメール**を追加します。
   - 公開ステータスは「テスト」のままにします。審査は不要で、無料で使えます。
4. 「クライアント」→「クライアントを作成」を開きます。
   - 種類：**ウェブ アプリケーション**
   - 承認済みのJavaScript生成元：`https://makoto6709.github.io`（末尾の`/`やパスは付けません）
   - リダイレクトURIは空のままにします。
5. 表示された「クライアントID」（`…apps.googleusercontent.com`）を控えます。これは公開しても問題ない値です。クライアントシークレットは使わないので、誰にも渡さないでください。

## B. 共有DBと共有カレンダーの準備（初期設定スクリプト）

1. https://script.google.com/ →「新しいプロジェクト」。名前は「MyLife Calendar 初期設定」にします。
2. `backend/Setup.gs`の中身を貼り付けます。先頭の`SETUP`に次の値を入力します。
   - 本人のメール
   - 恵里子さんのメール（本人が確認したもの）
   - 手順AのクライアントID
   - 辻岡シフトのID
   - 以前の版で作った共有DB・共有カレンダーがあれば、そのID（なければ空欄のまま）
3. 関数`setupMyLifeShared`を選んで「実行」を押します。権限の確認画面では、本人のアカウントで許可してください。
4. 実行ログに出る1行のJSONをコピーします。このスクリプトは次のことを行います。
   - 共有DB「MyLife_共有予定_DB」と共有カレンダー「MyLife 共有」を、恵里子さんだけに共有します。カレンダーは「変更および共有の管理権限」で共有します。
   - 既存IDを指定した場合は検査だけ行い、見出しやデータは書き換えません。
   - 元のシフト表は名前を読むだけで、書き込みはしません。
5. 恵里子さんに届く共有の通知メールは、そのままで構いません。

## C. 本体gatewayのデプロイ

1. script.google.comで「新しいプロジェクト」を作り、名前を「MyLife Calendar 本体gateway」にします。
2. `backend/Code.gs`の中身を貼り付けます。
3. 「プロジェクトの設定」→「『appsscript.json』マニフェスト ファイルをエディタで表示する」をONにします。そのうえで、`backend/appsscript.json`の中身に置き換えます。
4. 「プロジェクトの設定」→「スクリプト プロパティ」に、次のプロパティを追加します。
   - プロパティ：`MYLIFE_CONFIG`
   - 値：手順BでコピーしたJSON
5. エディタで関数`doGet`を1回「実行」し、「外部サービスへの接続」を許可します。
6. 「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」を選びます。
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
7. 発行されたウェブアプリURL（`https://script.google.com/macros/s/…/exec`）を控えます。ブラウザで開いて`{"ok":true,"version":3,"protocol":3}`と表示されれば成功です。

「全員」にしても、匿名で予定を読めるようにはなりません。全リクエストで次の条件をすべて確認し、どれかを満たさなければ拒否します。
- Googleのアクセストークンが、このアプリのクライアントID向けであること
- 2人のメールのallowlistに含まれること
- 保存先の共有権限が正しいこと

Sheets/Calendarの操作は常に呼び出した本人のトークンで行い、gatewayの所有者の権限は使いません。

## D. 公開アプリへの設定

`deployment.js`に、クライアントIDとgatewayのURLだけを設定してGitHub Pagesへ反映します。
- メール、各種ID、トークンは書きません。
- `?v=`の版番号と`service-worker.js`のキャッシュ名を更新します。

## E. 旧勤務用GASのトリガー確認

1. 「MyLife Calendar 勤務同期」プロジェクトを開きます。
2. 左の「トリガー」（時計アイコン）で、`syncMyLifeShifts`のトリガーが残っていないか確認します。
3. 残っていれば、エディタで`disableMyLifeAutoSync`を実行します。このプロジェクト自身のトリガーだけを解除し、他のアプリのトリガーには触りません。
4. 旧ウェブアプリは本体から呼びません。不要なら「デプロイを管理」→「アーカイブ」します。

## 利用開始（2人それぞれのiPhone）

1. Safariで公開URLを開き、「Googleで接続」を押します。自分のアカウントを選んでください。
   - テストモードのため「Googleはこのアプリを確認していません」と表示されます。「続行」で進めます。
2. 初回接続時に、本人専用の「MyLife_個人予定_DB」と「MyLife 個人」カレンダーが自動作成されます。これらは誰にも共有されません。
3. 「すべて同期」を押すと、次の2つを実行します。
   - 勤務の取得
   - Google Calendarとの双方向同期
4. 恵里子さんのアカウントには元シフト表の閲覧権限がないため、勤務は「対象外」と表示されます。本人が取り込んだ勤務は共有DB経由で2人に表示されます。

## 用語の区別

- **Googleアカウント（ログイン）**：MyLifeの予定をGoogle Sheetsへ保存し、勤務元を読むために必要です。
- **Googleカレンダー連携（ON/OFF）**：「すべて同期」でGoogle Calendarと送受信するかどうかの設定です。
  - OFFにしてもログインと保存済み予定は保持され、「すべて同期」は勤務だけを取得します。
  - Google側の許可そのものを取り消す場合は、Googleアカウントの「サードパーティ接続」で行います。

勤務の時刻が未入力の日（勤務先が空欄、または「勤務先」「開始時間」「終了時間」の見出しだけの日）は、既存の勤務を保持します。勤務を削除するのは、H・休・公休・休日・有休・有給・休み希望と明示された日だけです。取得失敗・不正時刻・未知の店舗では処理を停止し、予定は消しません。
