# iPhone起床アラーム：設定手順と実機確認

実装状態：時刻の計算ロジックは自動テスト済み。以下は手動構築するショートカットの手順であり、署名済みショートカットファイルや動作確認済みiCloudリンクはまだありません。iPhone実機でアクション名と動作を確認して完成させます。

## 参照する予定

iPhoneの設定 → アプリ → カレンダー → カレンダーアカウントで自分のGoogleアカウントを追加し、「カレンダー」を有効にします。iPhone標準のカレンダーで「MyLife 共有」が見えることを確認します。勤務はv2.3から共有カレンダー「MyLife 共有」に「【勤務】」で始まる予定として入ります。共有Googleカレンダーが一覧に出ない場合はGoogle側の同期対象カレンダーを設定します。

「MyLife 共有」以外のカレンダーから勤務を推測しません。勤務をする本人のiPhoneに設定します。恵里子さんの端末に同じアラームを作る必要はありません。

## ショートカット「MyLife 起床更新」

1. 「現在の日付」を取得。「日付を調整」で1日追加し、その日の開始を取得して「明日0時」とします。さらに1日追加して「明後日0時」とします。
2. 「カレンダーイベントを検索」で、カレンダー=MyLife 共有、開始日が明日0時以上・明後日0時未満、タイトルが「【勤務】」で始まる、開始日の昇順を指定します。終日イベント（時間未定の勤務）は除外します。検索結果の最初を翌日の勤務とします。
3. 検索に失敗・アクセス拒否なら通知して終了します。取得0件を休日と扱う前に、標準カレンダーの同期が正常であることを初回確認してください。標準カレンダーのオフラインキャッシュが最新かどうかを、この手順のみで保証することはできません。
4. 勤務がある場合、タイトルに水戸内原があれば通勤15分、東海なら45分、下妻なら90分。不明なら通知して終了し、既存アラームを変更しません。
5. 勤務開始から通勤時間と40分を引いて基準日時を取得します。さらに10分前・5分前・基準日時の3日時をリストにします。
6. 3日時が翌日に収まり、過去でないことを確認します。日付をまたぐ特殊な早朝勤務は通知して手動確認します。時計のアラームは日付を持たないためです。
7. 「すべてのアラームを取得」。各アラームの名前／ラベルが「MyLife-」で始まるものだけを繰り返して「アラームを切り替える」をオフ固定で実行します。「切り替え」のトグル動作にはしません。個人用・睡眠のアラームは対象外です。
8. 勤務0件ならここで終了。勤務があれば3日時それぞれについて続行します。
9. 日時を「HHmm」でフォーマットし、ラベルを「MyLife-0755」のように作ります。「すべてのアラームを取得」の結果を繰り返し、ラベル完全一致を探します。
10. 一致があれば最初の1個だけをオン固定にします。なければその時刻で「アラームを作成」、ラベル=作ったラベル、繰り返しなし、作成画面の表示が選べる場合はオフにします。同じ時刻のアラームを再利用するため、日々同じものを追加しません。
11. 3件をオンにした旨と時刻を通知します。過去のMyLifeアラームはオフのまま保持し、同時に有効になる重複を避けます。未使用のオフアラームを自動削除する方式は採用しません。不要になったものは時計アプリで手動整理できます。

各アクションの日本語名・アラームの名前を取得する方法・作成時に自動的に有効になる挙動はiOSのバージョンで確認が必要です。この手順は実機で未検証です。初回のカレンダー／時計／通知権限は手動実行で許可してください。

## 21時の自動実行

ショートカット → オートメーション → ＋ → 時刻 → 21:00・毎日 → 「すぐに実行」（旧表示では「実行の前に尋ねる」をオフ）→ 作成した「MyLife 起床更新」を実行。

Appleの公式案内では「時刻」の個人用オートメーションは確認なし実行に対応します。個々のアクションで確認が必要な場合は実機で設定します。

## 実機テスト（必須）

- 水戸内原9時勤務：07:55 / 08:00 / 08:05の3件
- 東海9時勤務：07:25 / 07:30 / 07:35
- 下妻9時勤務：06:40 / 06:45 / 06:50
- 同じショートカットを2回実行して有効なアラームが3件のまま
- 翌日をHへ変更し、GAS同期後に再実行するとMyLifeだけオフ
- 出勤時刻変更後に旧時刻がオフ、新時刻3件がオン
- 個人アラームが一切変わらない
- iPhoneロック中・21時・通信切断・Google認可解除・勤務先不明での挙動
